# MASTER PROMPT: Build a Premium HR Management Dashboard

Act as a senior frontend engineer, UI/UX designer, and Next.js architect. Build a beautiful, production-quality HR management dashboard for our existing HR Onboarding & Offboarding Portal.

IMPORTANT: This is the authenticated internal dashboard, not the public landing page. It must maintain the same visual identity as our existing homepage while being practical for daily HR operations.

The design should feel like a premium modern SaaS application: warm, elegant, fluid, spacious, and professional. Use soft cream backgrounds, blush pink accents, peach and lavender highlights, subtle glass effects, smooth transitions, and carefully crafted data visualizations.

Do not create a generic admin template. Build a distinctive, coherent HR workspace.

## 1. Existing technology stack

Use the existing project wherever possible:

- Next.js App Router
- TypeScript with strict typing
- Tailwind CSS
- shadcn/ui as the primary component library
- Selected 21st.dev components where they improve the design
- Lucide React icons
- Motion for React for animations
- Firebase Authentication for HR login
- Spring Boot REST APIs for backend functionality
- PostgreSQL as the application database

Use Recharts for charts only if the project does not already have a suitable charting solution.

Do not add Material UI, Aceternity UI, Magic UI, or additional component libraries indiscriminately. Prefer the existing shadcn/ui design system and selectively integrate compatible components.

First inspect the existing repository, homepage, routing, authentication setup, installed packages, and design tokens. Reuse existing components and styling. Do not replace the existing homepage or break current functionality.

## 2. Theme and design system

The dashboard must match the public homepage.

Use these colors as the foundation:

- Main background: `#FFFBF7`
- Secondary background: `#FFF4E8`
- Blush pink: `#F8DCE5`
- Rose accent: `#EFB7C8`
- Soft peach: `#FFE2D0`
- Lavender: `#EAE4FA`
- Butter yellow: `#FFF1BF`
- Primary text: `#443942`
- Secondary text: `#81747D`
- Card background: `#FFFFFF`
- Border: `#F0E5E5`

Design rules:

- Keep the interface light.
- Never use dark mode or large dark background surfaces.
- Avoid dark navy, saturated blue, and dominant green.
- Use charcoal-brown text for readability.
- Use pastel accents to distinguish different categories.
- Use soft shadows, thin borders, and restrained glassmorphism.
- Keep the interface spacious and easy to scan.
- Avoid excessive rounded cards and excessive gradients.
- Use consistent spacing, typography, and icon sizing.

Use Manrope or Plus Jakarta Sans for headings and Inter or Geist for body text, reusing the homepage typography if already configured.

## 3. Overall dashboard layout

Build a responsive application shell with three main parts:

1. A collapsible left sidebar.
2. A top navigation and utility bar.
3. A scrollable main content area.

On desktop, use a persistent sidebar with a comfortable width of approximately 250px. Allow it to collapse to an icon rail.

On mobile, replace the sidebar with an accessible slide-out navigation drawer.

The sidebar should use a warm cream surface with a subtle border and a restrained blush-pink active state.

The main content area should use a very light cream background. Cards should primarily be white with subtle pastel details.

Do not make the entire interface translucent. Reserve glass effects for floating panels, menus, and selected highlights.

## 14. Firebase authentication and security

Integrate with the existing Firebase Authentication implementation.

Requirements:

- Support Google and email/password sign-in through the configured Firebase project.
- Protect the dashboard from unauthenticated users.
- Verify Firebase ID tokens on the Spring Boot backend.
- Enforce HR permissions on every protected backend endpoint.
- Use an approved HR-user registry or properly configured custom claims.
- Do not assume that every authenticated Google user is authorized to view HR data.
- Handle expired sessions and logout correctly.
- Avoid exposing Firebase Admin credentials in the frontend.
- Do not store sensitive authentication tokens in insecure custom storage.
- Do not rely on client-side route protection as the only security mechanism.

Reuse the existing authentication flow rather than creating a second incompatible login system.

- Fetch dashboard summary.
- Fetch employee status distribution.

- Fetch recent notification logs.
- Search and paginate employees.
- Fetch current HR user information.
- Retry eligible notification jobs.

Use the actual backend endpoint paths and response schemas discovered in the repository.

Do not invent endpoints and pretend they exist.

Include:
- Loading skeletons.

- Empty states.

- Typed API response models.
- Consistent error messages.
