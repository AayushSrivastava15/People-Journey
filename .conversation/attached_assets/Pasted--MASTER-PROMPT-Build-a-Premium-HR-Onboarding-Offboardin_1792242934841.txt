# MASTER PROMPT: Build a Premium HR Onboarding & Offboarding Portal Homepage

Act as a senior UI/UX designer, creative frontend engineer, and Next.js architect. Design and implement a visually stunning, production-quality homepage for an **HR Onboarding & Offboarding Management Portal**.

The website should feel like a premium modern SaaS product, combining the polish of Linear, the softness of a contemporary editorial website, the fluidity of liquid glass interfaces, and the warmth of a pastel design system.

Do not create a generic admin dashboard or a boring corporate HR website. The design must feel thoughtfully art-directed, visually rich, fluid, modern, and professional while remaining easy to use.

## 1. Technology stack

Use the following technologies:

- Next.js with App Router.
- TypeScript with strict type checking.
- Tailwind CSS.
- shadcn/ui as the primary component system.
- Selected 21st.dev components for distinctive UI elements and visual effects.
- Lucide React for icons.
- Motion for React (`motion`) for smooth animations and transitions.
- Aceternity UI or Magic UI selectively for suitable animated components, after checking compatibility with the existing project.
- React Hook Form and Zod if functional forms are needed.
- `next/font` for optimized typography.

Material UI may be used selectively only if an existing project requirement justifies it. Do not mix multiple component systems indiscriminately. Maintain one consistent visual language.

First inspect the existing project structure, installed dependencies, current routes, and Tailwind configuration. Reuse the current setup wherever possible. Do not overwrite working configuration or introduce duplicate libraries unnecessarily.

## 2. Visual direction and color palette

Create a light-only visual experience with a sophisticated pastel color palette.

The dominant visual mood should be warm cream, blush pink, soft peach, and muted lavender, with subtle warm gray and restrained charcoal text for readability.

Use these approximate design tokens:

- Main background: `#FFFBF7`
- Warm cream: `#FFF4E8`
- Blush pink: `#F8DCE5`
- Soft rose: `#EFB7C8`
- Peach: `#FFE2D0`
- Lavender: `#EAE4FA`
- Pale butter yellow: `#FFF1BF`
- Soft coral accent: `#F29A9A`
- Primary text: `#443942`
- Secondary text: `#81747D`
- Card background: `#FFFFFF`
- Borders: `#F0E5E5`

Use a subtle pastel gradient system featuring cream-to-pink, peach-to-lavender, and blush-to-white transitions.

IMPORTANT:
- Do not use dark mode.
- Do not use black backgrounds.
- Do not use dark navy backgrounds.
- Do not use saturated blue or green as dominant colors.
- Avoid aggressive neon colors.
- Maintain strong text contrast despite the soft palette.
- Use darker colors only for readable text, not as large background surfaces.

Do not make every section a glass card. Mix clean solid surfaces, editorial layouts, soft gradient panels, and selective glass layers.

Avoid excessive shadows, excessive rounded containers, repetitive cards, and the generic AI-generated website look.

## 4. Homepage navigation

Create a polished, responsive navigation bar.

Include:

- A custom HR portal wordmark and minimal icon.
- Navigation links: Home, Features, How It Works, and About.
- A subtle status indicator such as “Your people, thoughtfully managed.”
- A primary “HR Login” button.
- A mobile navigation drawer with a smooth opening and closing animation.

The navigation should initially appear clean and lightweight. When scrolling, it should transition into a subtly translucent cream glass surface with a thin border and gentle backdrop blur.

Use sticky positioning only if it improves the experience.

All navigation links should scroll to their corresponding homepage sections. The HR Login button should navigate to `/login` if that route exists, or use a clearly defined route placeholder without breaking the build.

## 6. Liquid and fluid interactions

Add carefully designed motion throughout the page.

Implement:

- Slowly drifting pastel gradient orbs.
- Gentle floating movement on selected decorative elements.
- A liquid-style animated gradient in the hero background.
- Subtle parallax movement on decorative shapes.
- Soft hover lift on important cards.
- Smooth button hover transitions.
- Gentle spring-based motion when opening menus.
- Scroll-triggered fade and slide-in animations.
- A restrained reveal sequence for hero elements.
- A subtle animated progress indicator in the dashboard preview.
- Smooth transitions between sections.

For liquid effects, use lightweight CSS gradients, animated background positions, SVG filters only where appropriate, and Motion for React.

If using an SVG displacement filter, keep the effect subtle and provide a graceful fallback for browsers where it is unsupported.

Avoid expensive WebGL effects unless absolutely necessary.

Animations should feel fluid, not bouncy or distracting. Do not animate every element simultaneously.

Respect `prefers-reduced-motion`. Disable or reduce nonessential animation for users who prefer reduced motion.

## 7. Smooth scrolling experience

Implement a polished scrolling experience:

- Smooth anchor navigation.
- Scroll-triggered section reveals.
- Natural easing.
- Subtle background transitions between sections.
- A small, elegant scroll progress indicator if it complements the design.
- Gentle parallax only on decorative elements.

Prefer native CSS smooth scrolling for simple anchor navigation. Use Motion for React for reveal animations and interactive transitions.

Do not install Lenis or another scrolling library unless the existing implementation genuinely needs it. If a smooth-scroll library is used, avoid conflicts with browser navigation, sticky positioning, and reduced-motion preferences.

Scrolling must remain smooth on mobile and lower-powered devices.

Do not hijack scrolling or prevent normal browser behavior.

Build reusable components, for example:

- `Navbar`

- `ProductPreviewSection`

## 14. Responsive design

The homepage must work beautifully on:

- Large desktop monitors.
- Standard laptops.
- Tablets.
- Mobile phones.

Requirements:

- No horizontal overflow.
- No clipped headings.
- No overlapping floating cards on mobile.
- Navigation must collapse cleanly.
- Feature layouts must adapt naturally.
- The dashboard mockup must simplify or stack on smaller screens.
- Buttons must have comfortable touch targets.
- Decorative animation must not harm readability.
- Typography must scale smoothly with responsive CSS sizing.

Test the layout at narrow mobile, tablet, laptop, and large desktop viewport sizes.

## 15. Performance and accessibility

- Use optimized Next.js font loading.
- Avoid unnecessary client-side JavaScript.
- Use CSS animations for simple decorative effects.
- Avoid excessive blur filters on large surfaces.
- Avoid layout-shifting animations.
- Use `IntersectionObserver` or Motion's viewport capabilities for scroll reveals.
- Respect reduced-motion preferences.
- Ensure sufficient color contrast.
- Add meaningful accessible labels.
- Keep interactive controls keyboard accessible.
- Avoid unnecessary dependencies.
- Prevent hydration mismatches.
- Ensure no console errors are introduced by the implementation.

## 16. Implementation rules

1. Inspect the existing repository before making changes.
2. Identify the actual Next.js version, installed packages, routing structure, and styling system.
3. Reuse compatible installed dependencies.
4. Install only the additional libraries that are genuinely required.
5. Implement the homepage in the existing project rather than creating an unrelated replacement application.
6. Preserve all existing backend integrations and unrelated functionality.
7. Do not hardcode secrets, API credentials, or Firebase configuration secrets.
8. Do not create fake authentication behavior.
9. Do not connect the homepage to a nonexistent API.
10. Use clearly identified mock data only for visual previews.
11. Ensure all links and buttons have meaningful destinations or actions.
12. Do not stop after generating a static mockup. Implement the actual responsive React components, styles, and interactions.
